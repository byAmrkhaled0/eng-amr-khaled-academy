# سير العمل وسجل القرار

افحص ← أثبت المشكلة ← أصلح بأصغر تغيير متماسك ← اختبر السلوك ← وثّق الدليل والحدود.

نسخة الأساس: الملف المرفق 67.8.4، commit bf098c9. فرع المراجعة review/data-integrity. لا نشر إنتاجي، لا مراسلات، لا اختبارات حذف على بيانات حقيقية، ولا أسرار جديدة. الملفات التاريخية AUDIT_* مراجع فقط وليست إثبات تنفيذ.

قرارات هذه الدفعة:

1. حافظ على Vanilla JS/Firebase؛ استخرج الحسابات المشتركة إلى functions/lib بدل ملف patch جديد.
2. استعادة merge تحافظ على الغائب وتراجع SHA-256 والمشروع والصيغة. ارفض تعارض المال؛ لا تنفذ rollback مالي فوق دفتر حي. تحقق optimistic concurrency بين المعاينة والكتابة واحفظ نسخة أمان وسجل فشل جزئي.
3. الخزنة تقرأ الفترة الكاملة على الخادم وتعرض 40 صفًا؛ لا تعتمد إجمالياتها على أول 200 طالب أو 500 ملخص. cold reads الكاملة ما زالت مجال تحسين موثق.
4. التقرير يستبعد الدرجة المعلقة، يجمع المحاولات لكل امتحان، ويشترط إثبات اكتمال جدول الحصص؛ لا يخترع استحقاقًا ولا يسرّب student.notes.
5. الحضور يعتمد تجهيز حصة معتمدًا من الخادم ورمز attendanceCode وIndexedDB ومعرف طالب/حصة؛ الجلسة المحلية لا تمنح إذن المزامنة.
6. طلب الهيدر: العملي والنظري رابطان متجاوران، مع إصلاح CSS الذي كان يخفي النظري على سطح المكتب وتداخل الهيدر مع قائمة الهاتف.
7. رفع الإصدار إلى 67.8.5 لكسر كاش الأصول المعدلة. لا تعِد استخدام 67.8.4 للأصول المنشورة.

لتقليل إعادة العمل: ابدأ بجدول REVIEW_REPORT_AR.md وأدلة evidence ثم الملفات المتأثرة فقط. شغّل اختبار النطاق بعد كل دفعة، ومجموعة التكامل عند تغيير المعاملات/القواعد. فشل Storage الأول كان من مرور اتصال المحاكي المحلي عبر proxy بيئة الاختبار؛ نجح عند تشغيل loopback مباشرة دون تغيير الصلاحيات. أُعيد ملف اعتماد التشخيص لحالته، ولا يُشحن node_modules.

الباقي ليس «مطبقًا» لمجرد وجود هذا الملف: هاتف حقيقي وأوفلاين إعادة إطلاق PWA/الكاميرا، PDF عربي مُصدّر، مراقبة إنتاجية P95، ميزانية فعلية، تحقق IAM/الفهارس المنشورة، استرداد كائنات Storage، واستعادة مالية معزولة. لا تعلن اكتمال هذه البنود دون أدلة جديدة.
